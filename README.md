# 京东搬运助手 JDMove（Chrome 插件）

采集京东商品详情页和京东万商（`b2b.jd.com`）商品详情页（标题、参数、主图、详情图、规格），在京东 VC 自营供应商后台（发布页在 `wares-jdm.jd.com/vcProductPublish`）自动填写表单、上传图片，然后保存草稿，由你到草稿箱检查后再提交。插件只支持发布到 VC 自营，不再支持 POP 店铺。

## 安装

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本目录（包含 `manifest.json` 的 `JDMove` 文件夹）。
3. 在插件详情页打开 **「在无痕模式下启用」**（采集需要，见下文）。

## 为什么采集要用无痕窗口

京东不允许**商家账号**查看其他店铺的商品详情，会跳到 `bizsafe-intercept.jd.com`，提示“请使用消费者购物账号”。同一个 Chrome 用户下所有 `*.jd.com` 页面共用一套登录状态，所以：

- **发布**：直接在任务面板所在的浏览器窗口里新开标签页进行，使用你已登录的商家后台，不会另外弹出窗口。
- **采集**：插件会打开一个**无痕工作窗口**（Cookie 与普通窗口隔离）。第一次请在这个无痕窗口里登录一个**消费者京东账号**，之后可以连续采集；关闭所有无痕窗口后需要重新登录。

也可以在另一个 Chrome 用户 / 另一台电脑里安装插件采集，然后在任务面板中「导出采集数据」，到商家这边「导入」后再发布。

## 采集京东万商商品

粘贴万商商品链接（`https://b2b.jd.com/goods/goods-detail/100289450311?...`）即可，插件按链接自动识别平台，后续的编辑、保存到本地、发布流程和京东商品一样。

- **账号**：先在 Chrome 普通窗口登录万商账号。万商商品固定在普通窗口采集，不使用无痕窗口，也不受“商家账号不能看其他店铺商品”的限制；同一批里混有京东商品时，京东商品仍按设置走无痕窗口。
- **价格**：取页面主价格，即当前账号的**采购价**，不是建议零售价。“检查京东今日价”对万商商品读取的也是采购价（日志标注“万商采购价”）。
- **图片**：图片水印只是页面上的覆盖层，采集到的是原图。详情图优先用页面数据里的切片列表（750 宽，不用再切），没有时取图文详情里的 `<img>` 和模块背景图。
- **规格**：与京东相同，默认只采集链接对应的规格；勾选“采集全部规格”后带上全部。万商每个规格的采购价也不同，请核对售价。
- **无权限商品**：页面显示“暂无购买权限”的商品没有商品信息，该条标记为失败并写明原因。
- **发布**：和京东商品相同。源页面有“建议零售价”且不低于售价时直接使用（否则按售价 × 1.1 计算）；设置里的“包装清单”留空时填采集到的包装清单。
- 暂不支持从万商搜索/列表页批量提取商品，请粘贴商品链接或在商品页点「搬运此商品」。

## 发布到 VC 自营店铺（供应商后台 vcp.jd.com）

插件只发布到 **VC 自营**（旧版本的 POP 店铺发布、批量改价已删除；旧设置里的“POP 店铺”“提交并上架”读取时自动改为 VC、保存草稿）。插件这样处理：

- **不搜索类目**：京东自营和 VC 后台用同一套类目 ID、品牌 ID，插件直接用采集到的四级类目和品牌 ID 打开 `wares-jdm.jd.com/vcProductPublish/?bId=品牌ID&categoryId=末级类目ID`。品牌必须是账号已授权的品牌、类目必须在账号产品线里，否则页面会跳回京麦首页（该条标记为失败并说明原因）。也可以在「编辑」里指定类目ID路径和品牌ID，或用「类目映射」。**之前采集的商品没有这些数据，需要重新采集。**
- **5 个手动字段**：市场价、京东价、采购价、采购员ERP、销售员ERP。可以在「编辑 → VC 自营」里逐个填写，商品多时用**表格批量导入**（见下一节）。3 个价格缺任何一个都不会打开发布页；采购员和销售员可以是不同的 ERP，单个商品没填时用设置里的“默认采购员/销售员 ERP”，都没有时沿用页面默认的采购员/销售员。发布时在页面上输入 ERP 并选中对应的人。京东价不能高于市场价；采购价不低于京东价时会提醒毛利为负。
- **标题**：去掉品牌和【】里的宣传语（页面会自动加品牌前缀），上限 60 字符（汉字算 2）。
- **型号、包装长宽高、毛重**：用采集到的商品主数据，缺了在「编辑」里补。POP 店铺的商品主数据里型号常是空的，这时用货号（主数据或参数里的“货号”），并在日志里提醒核对；长宽高常是 0，京喜等店铺还会填占位值（1×1×1 mm、0.01 kg），这两种都当成没有，发布前拦下并写明原因，重新采集也不会有，请在「编辑 → VC 自营」中填写。销售单位按“包装形式”参数或规格推断（如“箱装”→ 箱），也可在设置里固定；包装规格、商品包装、质保期用设置里的默认值；包装清单按「编辑」> 采集到的包装清单 > 设置 >“类目名*1”。
- **字段格式**（按页面自己的校验规则，打开发布页之前就检查，不合规的不打开页面）：市场价、京东价最多 2 位小数，采购价最多 4 位；包装长宽高是整数 mm（采集到小数时四舍五入），毛重 0.01 kg 起、最多 3 位小数（4.33 原样填写）；长宽高、毛重的上限按类目不同，有上架模板时按模板（见“VC 上架模板”），没有时按长 4000、宽 3040、高 3000 mm、毛重 60000 kg。
- **图片**：方图上传到图片空间后选中；**透图**（必填，1 张 PNG）由第一张主图自动去白底生成，请在页面上核对效果；“图片信息识别”勾选刚上传的第一张主图后点“开始识别”→“补充数据”（已填的内容不变，只补空白字段）。上传的文件名带时间戳，如 `jdmove_vc_<SKU>_<时间>_m0.jpg`。
- **SKU 表**（单规格）：商品名称 = 标题 + 规格里标题没有的内容（≤60 字符）；规格按类目的结构化字段填写（如层数 3 层、单包抽数 100 抽 × 包数 36 包），填不好就跳过（单规格可以不填）；SKU属性按采集到的参数填写（下拉、带单位的数字、纸张尺寸这类长×宽都会自动拆开）；商品条形码用「编辑 → UPC」或采集到的真实条码（没有统一的默认条码），页面提示“条形码重复，可正常发品但入仓需贴码”时只记日志。
- **提交**：VC 自营一律点“**保存草稿**”（不点“发布商品”），请到 VC 后台草稿箱检查后手动提交；设置“填写完成后”选“只填写，不保存”时不点按钮，停在发布页。保存成功后日志里写出草稿编号；草稿箱满时页面会问“继续保存”（会删掉最早的草稿），插件不替你点，该条标为「需处理」。

### 表格批量导入市场价 / 京东价 / 采购价 / 采购员ERP / 销售员ERP

几百个商品逐个点「编辑」太慢时，用任务面板工具栏的「**表格导入价格/ERP**」（只在“发布到”选 VC 自营时显示）：

1. **下载模板**：弹窗里点「下载模板」，得到一个 .xlsx，每个商品一行（任务列表里勾选了就只列勾选的，没勾选列出全部未发布的商品），列为：商品链接、SKU、商品标题（仅供核对）、市场价、京东价、采购价、采购员ERP、销售员ERP。已经填过的值会预先填好。
2. **填写**：用 Excel 或 WPS 打开填写后保存。也可以用自己的表格，只要有一行表头包含“商品链接”（或 SKU）列和这 5 列中的任意几列（表头可以写成“京东价（元）”“采购员 ERP”这样，上面有标题行也可以）。
3. **导入**：弹窗里「选择文件」选中填好的表格，插件先显示预览：每个商品哪一项从什么改成什么、哪些行有问题（写明第几行、为什么），核对后点「导入」。结果和有问题的行也会写进运行日志。

规则：

- **以商品链接为准**找到任务列表里的商品（京东、万商链接都可以，链接后面带什么参数都行）；SKU 列只用来核对，两者不一致时该行不导入。表格里有、任务列表里没有的商品不会自动添加，请先用「添加链接」加入。
- **空格子不修改**，原来填过的值保留；表格里只有某几列也可以（比如只导入 ERP）。
- **一行里有一个值不对，整行不导入**：价格不是数字、超出范围、小数位数超出（市场价/京东价最多 2 位、采购价最多 4 位）、京东价高于市场价、ERP 不是“字母/数字/点/下划线/横线”（填了姓名）。价格可以带 ¥、元和千分位逗号（1,299.00）。
- 同一个商品在表格里出现多行且值不同时，这几行都不导入；已发布的商品不修改。
- 采购员和销售员相同时两列填同一个 ERP；只填一列时只改这一项。
- 支持 .xlsx 和 .csv（UTF-8 或中文 Excel 默认的 GBK 编码都可以），读第一个工作表；不支持旧的 .xls，请另存为 .xlsx。CSV 用 Excel 打开时长 SKU 会显示成 1.00115E+11（后几位丢了），所以请保留“商品链接”列。
- 导入只改插件里的数据，不动店铺后台；之前发布失败/需处理的商品导入后会提示“已修改，尚未重新发布”，再点「发布选中」即可。

### 发布前检查（点「发布选中」后先弹出的窗口）

样品商品来自不同店铺（京东自营、POP、万商……），采集到的数据经常和 VC 上架模板对不上：缺必填属性、缺价格、尺寸是占位值。所以点「发布选中」时不再直接开始发布，而是先弹出「发布前检查」，把选中的每个商品和它对应的上架模板放在一起看，补齐后再发布：

- **每个商品一张卡片**：主图、源标题、SKU、来源（京东自营 / 京东 POP / 京东万商）、源类目，以及**上架模板**下拉框。模板按发布时用的类目自动匹配（手动指定的类目 > 类目映射 > 源商品类目，三级、四级类目都能匹配）。
- **按模板列出发布页要填的内容**：基本信息（标题、品牌ID、型号、条形码）、价格与采销（市场价、京东价、采购价、采购员/销售员 ERP）、包装与物流（长宽高、毛重——范围按这个类目的模板、包装清单）、图片（方图、详情图张数，透图由第一张主图生成）、模板里的**商品属性**和 **SKU属性**。每一项都写出发布时会填什么、从哪来（采集参数 / 规格 / 属性默认值 / 设置 / 默认值 / 手动填写）。
- **颜色**：红色是缺的或填不上的（必填没有值、超出类目范围、下拉值不在可选项里、京东价高于市场价）；橙色是用了默认值或推断、请核对（如长宽高是占位值按默认 100 mm 填、型号用的是货号、没有条形码）。卡片右上角写“齐全”或“缺 N 项”，并列出缺哪几项。
- **直接在卡片里补**：输入框留空表示用灰色提示里的自动值，填了就用你填的；属性是下拉框的选可选值，选“自动”改回按采集数据匹配。填的内容存进商品的「编辑」里（价格/ERP/型号/长宽高 → 编辑 → VC 自营，条形码 → UPC，属性 → 属性覆盖），和在「编辑」弹窗里改是一样的。
- **匹配不到模板时自己选**：源商品没有类目ID、或类目没有录制模板时，卡片上会说明，在下拉框里选一个模板即可——选模板就是把这个商品发布到该模板的 VC 类目（抽纸、卷纸要选到四级类目，如“抽纸 > 常规抽纸”）。没有模板的商品多时，用顶部“批量设置模板 → 设给没有模板的商品”。
- **表格批量填写**：顶部“下载填写表格”得到一个 .xlsx：每个商品一行，列有上架模板、基本信息、价格、物流，以及这批商品所有模板的属性（商品的模板没有的属性显示“—”）；“还缺”列写着现在缺什么，“可选值”表列出每个模板的属性和可选值。填好后点“导入填好的表格”，内容填进弹窗（还没保存），有问题的行写明第几行、为什么。规则同「表格导入价格/ERP」：按商品链接对应、空格子不修改、一行里有一个值不对整行不导入；模板列填模板名（如“湿巾”“常规抽纸”），填“自动”改回自动匹配。那张价格/ERP 表也可以直接导进来。
- **保存与发布**：齐全的商品默认勾选“发布”（也可以手动勾选/取消，“只勾选齐全的”一键勾选）。“保存并发布勾选的 N 个”保存所有修改并发布勾选的商品；“只保存修改”只保存不发布；“取消”或 Esc 时有未保存的修改会先确认。弹窗里的检查和发布流程用的是同一套规则，“齐全”的商品打开发布页前的检查也会通过（发布页上的属性仍以页面实际读到的为准）。

### VC 发布流程（插件按这个顺序执行）

1. **打开前检查**：类目ID、品牌ID、3 个价格、型号、长宽高、毛重、主图、详情图；价格/尺寸/毛重的格式和范围（见上面“字段格式”；有上架模板时长宽高/毛重按模板里该类目的上下限），以及上架模板里的必填商品属性。缺任何一项都不打开页面，标为「需处理」并写明缺什么。
2. **打开发布页** `wares-jdm.jd.com/vcProductPublish/?bId=品牌ID&categoryId=末级类目ID`，等表单就绪；跳回京麦首页/登录页时说明原因。
3. **读表单结构**（商品属性的选项），生成填写计划：标题、属性、SKU 商品名称、规格/SKU属性的取值。必填属性匹配不上时停下。
4. **基本信息与物流**：标题在输入框里输入；型号、市场价、京东价、采购价、长宽高、毛重、保质期、包装规格、销售单位、商品包装、质保期、包装清单**全部以文本写入**（和手动在输入框里输入一样），写完逐个读回核对。
5. **采购员/销售员**：填了 ERP 时在两个输入框里输入并选中候选人，没填沿用页面默认。
6. **商品属性** → **方图** → **透图** → **图片信息识别**（放图 + 开始识别 + 补充数据）→ **商品详情** → **SKU 表**（规格抽屉、商品名称、条形码、SKU属性抽屉）。
7. **页面本地校验**（表单校验 + “图片识别过没有”）；没通过就停下，保留页面。
8. **提交数据检查**：用页面自己的 `convertData()` 生成要提交的数据（不发请求），确认写过的字段没有变成带小数的数字。
9. **保存草稿**，按保存接口的返回判断结果：成功记下草稿编号并关闭页面；失败（如“无效的字符串，请核对后再试 [456]”）把页面原文写进日志并保留页面。

> **“无效的字符串/数字，请核对后再试 [456]/[455]”** 是 VC 网关拒收了提交数据里某个字段的格式。2026-11-08 实测：页面输入框产生的值全是文本，旧版插件把毛重写成数字 4.33，保存时报 [456]（同一个值写成文本 "4.33" 正常），这就是之前“毛重只能一位小数”的真正原因。新版插件所有字段都按文本写入并在保存前检查。如果仍然出现，请把日志里“提交数据里有带小数的数字”那一行发出来。

### VC 上架模板（templates/vc/）

按三级类目录制的 VC 发布页结构，一个类目一个 JSON 文件，`index.json` 是目录。每份模板记录：基本信息字段（是否必填、长宽高/毛重的上下限、销售单位等选项和页面默认值）、商品属性、规格抽屉的结构化字段（如层数、单包抽数 × 包数）、SKU 表的列和 SKU属性（含下拉选项的取值 ID）。数据直接取自发布页自己的表单规则，不含品牌、ERP、价格等账号或商品相关的内容。

已录制（2026-11-09）：家庭清洁/纸品 > 清洁纸品 下全部 9 个三级类目——乳霜纸、抽纸、卷纸、手帕纸、湿巾、厨房纸巾、湿厕纸、一次性清洁/护理纸品、洗脸巾/棉柔巾/绵柔巾。抽纸、卷纸在 VC 后台不是末级类目，模板分别按「常规抽纸」「有芯卷纸」录制，其下的四级类目共用（按三级或四级类目ID都能找到这份模板）。

注意：包装长宽高和毛重的上限按类目不同（如手帕纸长 ≤ 3000 mm、有芯卷纸长 ≤ 5000 mm，毛重上限 18500~90000 kg）；产品名称只有部分类目有，包装规格在洗脸巾、乳霜纸里是选填，销售单位在乳霜纸里是选填。

**发布时怎么用模板**：发布前按商品的类目ID路径找模板（三级、四级类目ID都能找到），日志里写“上架模板：家庭清洁/纸品 > 清洁纸品 > 抽纸（2026-11-09 录制）”。打开发布页之前：

- 包装长宽高、毛重按模板里**这个类目**的上下限检查（没有模板的类目仍按默认的 4000/3040/3000 mm、60000 kg）；
- 按模板检查**必填商品属性**能不能从源商品参数、「属性覆盖」或「属性默认值」里填上（和发布页上的匹配规则相同），填不上的列出来，不打开页面，标为「需处理」。

湿厕纸的必填商品属性「纸张尺寸」是长、宽两段数字（单位 mm，每段 0~999999999.999、最多 3 位小数），模板里记了每段的名字和单位（`segments`）。插件从采集参数「纸张尺寸」（如“长195mm 宽133mm”）、「属性覆盖」或「属性默认值」里取两个数字，写成“195*133mm”“20×14cm”也可以（cm 会换算成 mm），发布页上填成 `[{name:'长', unit:'mm', value:'195'}, {name:'宽', unit:'mm', value:'133'}]`。

打开发布页后，商品属性仍以页面上实际读到的为准；模板读不到时日志里说明，按默认规则继续。抽纸、卷纸的四级类目用的是同一份三级模板，如果某个四级类目的规则和录制用的不一样，以页面为准。

录制其他类目：打开该类目的 VC 发布页，在页面里执行 `src/inject/backend-vc-template.js`，再调用 `window.__JDMOVE__.backend.vcCaptureTemplate()`，得到的 `template` 就是模板原始数据（插件的 VC 桥接里也已带上这个方法）。

## 使用流程

1. 点击插件图标 →「打开任务面板」。
2. 「添加链接」：粘贴商品链接或 SKU，一行一个，也可以粘贴整段文本。全球购（`npcitem.jd.hk`）和京东大药房/京东健康（`item.jingdonghealth.cn`）的商品也可以采集：`item.jd.com` 的链接会自动跳到这两个域名，插件照常采集。也可以在商品页右下角点「搬运此商品」，或在店铺/搜索列表页用弹窗里的「提取当前页所有商品链接」。
   - 「抓取店铺」：填写店铺链接（店铺首页如 `https://mall.jd.com/index-1000078502.html`、“全部商品”页如 `https://mall.jd.com/view_search-646206-0-99-1-24-1.html`，或店内搜索结果页），插件会在采集窗口里打开店铺“全部商品”页，把所有商品加入任务列表（页间隔 3～6 秒）。在“全部商品”页选了分类后再复制链接，就只抓这个分类。
     - 不同店铺的装修模板差异很大，插件会：从页面隐藏字段读取店铺 appId（有些首页没有“全部商品”链接）；页面上有多个商品列表时逐个抓取并去重；跟着每个列表自己的“下一页”翻页（地址翻页、页内翻页都支持）；抓到的数量少于列表显示的总数时，换“上架时间”“销量”排序补抓。
     - 列表上每张商品卡片是一个 SPU（同一商品的多个规格），链接只指向其中一个规格。插件会把卡片下方规格缩略图里的 SKU 一起加入；缩略图正好 5 个（京东最多只显示 5 个，可能还有更多）或店铺模板不显示缩略图时，列表抓完后再逐个打开该 SPU 的商品页，读出全部规格的 SKU 编码，换成 `https://item.jd.com/{SKU}.html` 加入任务列表（同样间隔 3～6 秒；同一 SPU 的规格已经读到过的不会重复打开）。不区分是否有货。
     - 店铺“全部商品”页没有商品列表时，改用店内搜索兜底，日志会提示“结果可能不完整”，请核对数量。补抓后仍不足总数时，日志会写明“显示共 N 件，实际抓到 M 件”。
     - 遇到频控/验证，或商品列表一直显示“努力加载中”（京东接口限流）时会暂停，已抓到的商品会保留；等几分钟后重新点「抓取店铺」即可，已有的商品不会重复添加。
3. 「采集选中」：在无痕工作窗口中逐条打开并采集（关闭“无痕窗口采集”时改为在当前窗口新开标签页），每条之间随机间隔（默认 8～15 秒）。
   - 「存储位置」：选择电脑上的一个文件夹（建议新建一个，如“京东素材”）。设置后每采集完一条，会自动保存到 `存储位置/品牌/SKU/`：`主图/`、`详情图/`、`商品信息.txt`（便于查看）、`商品信息.json`（可用「导入」导回插件）、`原始数据.json`（采集时页面返回的原始数据和完整商品主数据，采集结果不对时把它发给开发者排查；只在采集时写，之后「保存到本地」不会覆盖）。同一品牌写法不同（如“华为（HUAWEI）”和“华为(huawei)”）会放进同一个品牌文件夹。
   - Chrome 重启后第一次点「采集选中」/「保存到本地」时，浏览器会询问是否允许写入该文件夹，点“允许”即可。
   - 「保存到本地」：把已采集但还没存到本地的商品补存一遍（例如在商品页用「搬运此商品」采集的）；勾选后点击则重新保存所选商品。任务列表里会显示每个商品的本地路径。
   - 「删除选中」/ 行内「删除」：删除任务时会同时删除该商品的本地文件夹（`品牌/SKU/`，含图片和商品信息），品牌文件夹删空后也会删除；删除前会弹窗确认。没有存储文件夹的访问权限时不会删除任务。
4. 检查 / 「编辑」：可以修改标题、VC 自营字段（市场价/京东价/采购价/ERP、型号、长宽高、毛重等）、UPC 和属性；也可以搜索并指定类目，勾选“记住”后，同一源类目以后会自动使用这个类目。
5. 「发布选中」：先弹出「发布前检查」（见上文），按上架模板核对、补齐每个商品要填的内容（可以选模板、用表格批量填写），点“保存并发布”后在当前窗口新开标签页打开 VC 发布页，按上面「VC 发布流程」填写，最后点“保存草稿”（设置里选“只填写，不保存”时停在页面）。请到 VC 后台草稿箱检查后手动提交。行内的「重新发布」不弹窗，直接发布。
6. 「已发布」：商品发布成功后会自动从任务列表移到「已发布」页，任务列表不再显示已发布的商品（再次添加同一个链接也不会重新加入任务列表）。「已发布」页按品牌把商品归到文件夹里，点击文件夹查看该品牌的商品，可按品牌名搜索；在这里「重新发布」时，即使失败也仍留在「已发布」页。
7. 「检查京东今日价」（在「已发布」页）：京东自营的价格每天在变（补贴价时有时无），可能出现京东价比你的售价还高、卖出一单就亏钱的“价格倒挂”。建议每天点一次：
   - 插件在采集窗口（与采集相同，无痕窗口 + 消费者账号）逐个打开已发布商品对标的京东商品页，只读取页面上显示的价格（京东价/补贴价等），不滚动、不取图，比采集快很多（间隔在设置里调，默认 3～6 秒）。
   - 范围：在文件夹列表页点时检查全部已发布商品；打开某个品牌文件夹时检查该文件夹；勾选了就只检查勾选的。没勾选时会跳过今天已经检查过的商品（中途暂停后再点一次即可接着检查）。
   - 京东今日价高于你填的 VC 京东价时，该行标红并写出“倒挂：每单亏 ¥x”；所有倒挂的商品会集中列在最前面的红色「价格倒挂」文件夹里（亏得多的在前）。设置里的“预警线”大于 0 时，VC 京东价比京东今日价高出不到这个数也会提醒（显示“利润仅 ¥x”）。
   - 对比用的售价是发布（保存草稿）时填的 VC 京东价；没有发布记录时用「编辑 → VC 自营」里填的京东价，都没有时不判断倒挂。
   - 某个商品这次没检查成功（页面打不开、已下架等）时，会写出原因并保留上次检查到的价格，倒挂提醒不会因此消失；下次点「检查京东今日价」会自动重试这些商品。

执行批量任务时请**保持任务面板标签页打开**。插件打开的发布/采集标签页会自动切到前台，执行期间不要切走或最小化窗口，否则页面的下拉框和弹层可能无法正常工作。插件驱动的标签页会自动跳过“离开此网站？”确认。

「编辑」里的“搜索店铺类目”在京麦类目选择页的“普通发品”里搜索（页面停在“智能发品”时会自动切过去）；类目选择页直接跳到了别的页面时会提示原因，请在「编辑」中填写类目ID路径，或在设置的「类目映射」中配置。

## 设置说明

| 项目 | 说明 |
| --- | --- |
| 采集间隔 | 京东对频繁访问有频控。遇到频控/验证页时任务会自动暂停，你手动处理后再点继续 |
| 标题 | 前缀、后缀、删除词；按京东规则（汉字算 2 个字符）截断到 60 |
| 填写完成后 | 保存草稿（默认）/ 只填写不保存。VC 自营一律只点“保存草稿”，不点“发布商品” |
| 属性默认值 | 源页面没有对应参数时使用，每行写一条“属性名=值” |
| 限流后冷却 | 保存时返回“操作过于频繁”（限流）后建议等待的分钟数，默认 60；这段时间内点「发布选中」会先提醒，0 = 不提醒 |
| 京东今日价检查 | 检查间隔；预警线（VC 京东价比京东今日价高出不到 N 元也提醒，0 = 只在倒挂时提醒） |
| 类目映射 | 每行写一条：`源类目路径 => 目标类目ID路径 \| 名称`。源类目路径是源面包屑中任意连续几级（如 `休闲食品>巧克力` 可覆盖牛奶/黑/白巧克力），多条命中时用级数最多的一条 |

## 注意事项

- **默认只采集当前链接这一个规格**。京东每个规格都是独立 SKU、价格各不相同，页面上只能拿到当前规格的价格。VC 发布目前只发单规格，多规格商品请把每个规格的链接分别添加进来。
- **采集时不要遮挡或最小化采集窗口**：京东商品页的“商品详情”要滚动到屏幕上才会加载，窗口在后台时浏览器不渲染页面，详情图就采不到。插件每采一条都会把采集窗口切到前台；详情区没加载出来时会切到前台再取一次，仍失败时提示“采集窗口不在前台，商品详情没有加载出来”，重新采集即可。
  - 有些商品的详情图写在京东的外部样式表里（京东新版页面自己不加载它，页面上看不到这些图），插件会单独下载这个样式表取出详情图。
  - 提示“商品详情已加载，但没解析出详情图”：样式表下载失败或京东页面结构又变了，先重新采集；仍失败请反馈这个 SKU。
  - 提示“京东商品页没有商品介绍图片”：详情区里既没有图片也没有图片模块，源商品本身没有详情图，重新采集也不会有。
- 价格取页面上实际显示的主价格（京东价，有补贴时为补贴价）。补贴可能随时取消，请每天用「已发布 → 检查京东今日价」核对是否倒挂。
- 「检查京东今日价」只读取商品链接对应的那一个规格；采集了全部规格的商品，其他规格的价格不会逐个检查。
- 源页面没有“净含量/规格”参数时，会从规格值或标题中识别“480g / 1.5L”这样的写法来填写。
- 源页面没有“包装/销售单位”参数时，会从标题、规格值里的“桶装、6袋装、礼盒、大礼包、组合装/混合装”等字样推断，都没有时再看类目名（如“饼干礼盒/礼包”）。例：“童趣礼盒330g”→ 包装=礼盒装、销售单位=盒；“组合装237g 大礼包”→ 包装=组合装、销售单位=组，京麦类目没有这两个选项时改用“大礼包”→ 袋装/袋。日志会提示“属性按推断填写，请核对”；看不出容器时仍会提示必填，请在「编辑 → 属性覆盖」或「属性默认值」中填写。
- **商品条形码**：SKU 表的“商品条形码”按「编辑 → UPC」> 采集到的条形码填写。京东主数据里的 `0000000000000` 这类占位值、SKU 编号、校验位不对的数字不算条形码。没有条形码时只提醒（自营商品入仓需要条形码），不使用统一的默认条码（同一个条码填到所有商品会被判重码）。
- **品牌必须是店铺已授权的品牌**，否则该条会标记为「需处理」。
- **限流**：保存时返回“操作过于频繁，请稍后再试”（bCode 10003）时，店铺暂时不能保存任何新商品。插件会暂停整批发布、关闭该发布页，没保存成功的商品回到“已采集”留在任务列表，日志里写出返回的 trace-id（可提供给京东客服）。任务面板顶部会显示建议的重试时间（设置里的「限流后冷却」），冷却期内再点「发布选中」会先确认。
- 自动匹配的必填属性如果没有填上，会在日志中列出来，请在「编辑 → 属性覆盖」中补上。
- 请确认你有权销售所搬运的商品，并遵守京东平台对图片和描述的使用规则。插件不会绕过京东的验证码或频控。

## 开发

```bash
npm test          # 单元测试（node:test，无依赖）
npm run coverage  # 覆盖率
npm run icons     # 重新生成图标
```

目录结构：

- `src/shared/`：纯函数，包括归一化、属性映射、VC 发布计划（`vc-plan.js`）、发布前检查（`vc-review.js`、`vc-review-attrs.js`，表格 `vc-review-sheet.js`）、类目映射与末级类目选择、价格检查、标题、设置、仓储、表格读写（`zip.js`、`xlsx-read.js`、`xlsx-write.js`、`table-file.js`，不依赖第三方库）和 VC 字段表格导入（`vc-import.js`），有单元测试覆盖
- `src/inject/`：注入页面主世界的脚本（`jd-item-extract.js` 用于京东商品页，`b2b-goods.js` + `b2b-item-extract.js` 用于京东万商商品页，`jd-shop-list.js` 用于店铺商品列表页，`backend-*.js` 用于 VC 发布页和类目选择页）。新增平台时增加一组提供 `extractItem` / `extractPrice` 的脚本，返回相同结构的原始数据，再在 `collector.js` 的 `itemPage` 里按链接选用
- `src/lib/`：扩展侧的流程编排（采集、VC 发布 `publisher-vc.js`、价格检查、图片处理、任务队列）
- `src/dashboard/`、`src/popup/`、`src/content/`、`src/background/`：界面和入口
